## Design and repository ownership

Single repository `swell` (owner: Misja), app id `harbour-swell`,
organization/application names for Sailjail decided at scaffold time.

C++/QML split. Each part records why it is in C++, as the spec requires:

| Part | Where | Reason |
|---|---|---|
| LSDP discovery (`bluos::Discovery`) | C++ | QML has no UDP socket. QUdpSocket on port 11430. Sends seven queries at 0, 1, 2, 3, 5, 7 and 10 s with up to 250 ms jitter (API v1.7 Appendix, timing) and keeps listening for announces. Handles Announce and Delete messages and skips unknown types. |
| LSDP packet parser (`lsdp::parse`) | C++, pure function | Tested with QtTest on synthetic byte arrays. Cases: truncated packet, unknown type, own echoed `Q`, several messages, an announcement split across messages (API Appendix note 2), a Delete message, the class filter, and an address change for the same node id. The control port comes from TXT `port`, falling back to 11000. Name and model are taken from TXT when present; `/SyncStatus` is authoritative. |
| Player client (`bluos::Client`, one per player) | C++ | Reason: the long-poll, one-second-rule and backoff state machine must be covered by QtTest (AC3). Timeouts use `QTimer` + `abort()`: Qt 5.6 has no transfer timeout in either QNetworkRequest or QML XHR, as checked in `libQt5Qml.so.5.6.3`. All clients share one QNetworkAccessManager owned by the player model. QML `Image` uses the engine's own NAM, which follows redirects itself. The one-second rule is keyed by request path (API §2: "must"). Bursts collapse to the latest value per path and parameter: a volume burst ends at the last level, and a mute in between is kept (result review 2026-11-06). Offline state and backoff. Commands: play, pause, skip, back, volume and mute. |
| Polling policy | C++ (`bluos::Client`) | `/Status` long poll with `timeout=100` (API §2.1 recommends 100 s and never less than 10 s; tests inject shorter values). `/SyncStatus` is fetched once when a player is added (name, model, id, group master) and again whenever `<syncStat>` in `/Status` changes. This player's volume and mute come from `/SyncStatus`, because a grouped secondary's `/Status` copies the primary's (API §2). |
| XML parsing (`parseStatus`, `parseSyncStatus`, `parseVolume`) | C++, QXmlStreamReader, pure functions | Unknown elements are ignored and malformed input returns an error value. QtTest coverage without a network. |
| Player model (`PlayerModel`) | C++ QAbstractListModel | Merges discovered and manual players by node id / `host:port`. |
| MVP: `Status.prid` | C++ (`parseStatus`) | Needed to know when presets change (API §2.1, §6.1). |
| MVP: preset and input parsers (`parsePresets`, `parseCaptureInputs`) | C++, QXmlStreamReader, pure functions | Done (40c5af5). Same reason as the other parsers: QtTest coverage of unknown elements, missing `inputType`, nested Hub `<category>`/`remoteitem` (skipped) and malformed input (AC2). Hub inputs are a scope choice: §11.1 is the only way to select them, so later support stays possible. |
| MVP: presets and inputs on `Client` | C++ | `presets` and `inputs` as `QVariantList` of `QVariantMap`, with image URLs already resolved. They are small and rarely change, so no list model. The client caches them per player: presets are fetched on first contact and on a `prid` change, so a player switch shows the cache at once; inputs come on first contact and via `refreshInputs()`, which Home calls when shown. `playPreset(id)` sends `/Preset?id=`. `playInput(url)` sends `/Play?url=` with the attribute byte for byte. Failures use the existing `commandFailed(path, error)`: `onCommandReply` also treats an `<error>` root body as a failure. No new signal. |
| MVP: command query encoding | C++ (`bluos::Client`) | The gate stores the already-encoded query string, not a `QUrlQuery`, because `QUrlQuery` decodes `%3A`, `%2F` and `%2C`. Normal commands use `QUrlQuery::query(QUrl::FullyEncoded)`. Inputs use `"url=" + attribute`, set with `QUrl::setQuery(…, QUrl::StrictMode)`. An invalid result (a raw `#`, or `&` injection) is rejected and reported through `commandFailed`. Collapsing is keyed by path and parameter name (result review 2026-11-06), so `/Play` (play) and `/Play?url=` (an input) no longer replace each other. Both still share the per-path one-second limit; stream skip and back actions, which share `/Action?service`, collapse to the latest. |
| MVP: current player and polling policy | C++ (`PlayerModel`) + QML binding | `PlayerModel` gains `currentId` (read/write), `current` (`Client*`, NOTIFY) and `pollAll`. The model applies the policy in one place, including to clients created later: a client runs when `pollAll` is true or it is the current one; otherwise `stop()`. The existing `start()`/`stop()` suffice: `stop()` keeps the last status and `start()` resumes the long poll with the old etag. A stopped client keeps showing its last state, including "Online"; this is intended. QML binds `pollAll` to "Players page active and `applicationActive`". When the current player's client is replaced after an address change, `current` notifies, so QML never holds a deleted client. |
| MVP: start state | C++ (`PlayerModel`) + QML | The current player is persisted as `host:port` plus its LSDP `nodeId` (when known). At start the model creates that entry at once, so it shows Connecting instead of "not online" while discovery runs (up to ~10 s). An announcement with the same node id but a new address updates it (the existing address-change merge), so a DHCP change does not leave Home on a dead address. With a remembered player, start on Home; otherwise start on Players. If the current player is offline, Home shows its availability with a hint. |
| MVP: pages | QML/Silica | Players (`SilicaListView`, pulley: About, Add player, Search again; context menu Remove on manual players); Add-player `Dialog`; Home (presets grid, inputs row; pulley: Players, About); Now Playing via `pageStack.pushAttached` from Home; About with the privacy statement. Every page sets `allowedOrientations: Orientation.All`, because Silica defaults pages to portrait (`ApplicationWindow.qml:107`). Now Playing uses `isLandscape` to put the artwork beside the controls. |
| MVP: docked mini-player | QML, Silica `DockedPanel` | One panel declared in the `ApplicationWindow`. It reparents to `_rotatingItem`, so it follows the orientation (DockedPanel.qml:97-98). The window's `bottomMargin: panel.visibleSize` keeps page content clear in both orientations (ApplicationWindow.qml:315-316). Shown only on Home and Players, and only with a current player that is online. It is opened and closed through a `Binding`/`show()`/`hide()`, because dragging it sets `open = false` and would break a plain `open:` binding (DockedPanel.qml:258). It hides when the attached-page swipe starts. Landscape uses a compact height. It shows artwork, title and play/pause; a tap opens Now Playing. `MediaPlayerControlsPanel` is not reused (seek slider always shown, no artwork/title slot, opens only while playing). |
| Cover page and cover actions | QML/Silica | `CoverActionList`: play/pause and next. |
| Persistence (manual hosts, current player) | QML `Nemo.Configuration` (`ConfigurationValue`) | Existing allowed platform facility; no own storage code. |
| Cover art | C++ helper `artworkUrl()` + QML `Image` | The helper resolves relative image paths against the player and adds `followRedirects=1` (API v1.7 image attributes). `Image` loads through the shared NAM, which also follows redirects as a fallback. |
| Translations | `qsTr()` + `translations/*.ts`, `CONFIG += sailfishapp_i18n` | As in the SDK template. `lupdate` runs at build time and merges new strings without losing translations (checked 2026-11-06: only line references changed). Release check: no `type="unfinished"` left in a maintained language. The platform's `sailfishapp_i18n.prf` (libsailfishapp, read in the target 2026-11-06) does the work: `lupdate -noobsolete`, `lrelease -nounfinished`, install in `/usr/share/harbour-swell/translations`, loaded by libsailfishapp for the system locale at start. Misja 2026-11-06: keep `qsTr` (the SDK default), with `//:` translator comments where needed. `qsTrId` (`sailfishapp_i18n_idbased`, as in Jolla's own apps) stays an option. |

No threads besides Qt's own network handling; everything runs on the event loop.

Library (Misja, 2026-11-06: "a robust and current C/C++/QML lib"): the
protocol layer is a UI-free module `bluos/` inside this repository, with its
own `bluos.pri`, namespace `bluos` and tests. It depends only on Qt Core and
Network and targets API v1.7. A separate repository follows only after reuse
is demonstrated (workspace principle 9). Research 2026-11-06 found no
reusable C/C++ BluOS library (issue #1 comment).

Layout: `bluos/` (protocol library), `src/` (app C++), `qml/`, `translations/`, `rpm/harbour-swell.spec`,
`harbour-swell.desktop` (`[X-Sailjail] Permissions=Internet`;
OrganizationName must not be com.jolla or org.sailfishos), `icons/` with the
template's `SAILFISHAPP_ICONS = 86x86 108x108 128x128 172x172`, `tests/`
(QtTest, `CONFIG += testcase`, never installed), The RPM `%files` stay as in the template:
only `/usr/bin/harbour-swell`, `/usr/share/harbour-swell`, the desktop file
and the icons (the validator's `rpmvalidation.conf`). Configuration keys
live under `/<org>/harbour-swell/`; dconf is already allowed by
`Base.permission`.

Conventions (workspace principles 1.1.0, "Sailfish app conventions"; PR
misja/sailfish-workspace#18): Sailfish OS Coding Conventions (CamelCase
namespaces `BluOS`, `Lsdp`, `Swell`; QML braces, `_private` members, no
redundant defaults), the Silica pitfalls (touch targets ≥ `itemSizeSmall`,
pressed highlight colours, artwork flush with the edges) and the UI Definition
of Done. Every feature is checked against them before its result review.

## Validation

One gating test layer (A); the former Layer B is removed.

**A. In-process QtTest** (acceptance criteria 2 and 3; this layer gates
completion). Built with `CONFIG += testcase` and run with `make check` in the
SDK build engine for the aarch64 target (sb2/qemu; see the spike above):
- Parser and LSDP unit tests on synthetic fixtures written for this project.
- `PlayerClient` against a `QTcpServer` fixture in the same test process on
  loopback. It covers:
  - long-poll hold until the etag changes or the timeout expires;
  - an unchanged-etag timeout;
  - the one-second rule;
  - server stop/start, which must give offline then recovered;
  - a host that is not a BluOS player;
  - the request log for transport, volume and mute, including a collapsed
    volume burst;
  - `/SyncStatus` refetch on a `<syncStat>` change;
  - `/Artwork` redirect: an image fetched through a NAM with redirects enabled follows a
    redirect to a second fixture port, and `artworkUrl()` adds
    `followRedirects=1`;
  - MVP: presets and inputs fetched; `/Preset?id=` sent; for `/Play?url=` the
    fake player logs the raw request target, and it must equal `/Play?url=`
    plus the attribute byte for byte. One case uses the §11.1 shape with
    `%3F`, `%3D`, `%2C`; another contains `%25`; an input URL with a raw `#`
    is rejected. A `prid` change refetches `/Presets`. An `<error>` body raises
    `commandFailed`. The model's `pollAll`/`currentId` start and stop the right
    clients, including ones created later, and the remembered player appears
    at once as Connecting.
- QML engine test (AC4): every `.qml` file becomes a Ready `QQmlComponent` on
  the `minimal` platform with the target's import path. Files are loaded by
  `file://` URL from the source tree, so relative imports resolve. C++ types
  are registered through one shared function used by `main` and the test.
  A negative control (a deliberately wrong property) must give an Error
  status. The spike's root is an `ApplicationWindow` importing
  `Nemo.Configuration`. The Silica plugin links EGL/wayland/mlite, which the
  target has. Whether it survives engine initialization under `minimal` is
  open until the spike runs. The target has no
  `qmllint` and no offscreen platform (checked 2026-11-06), so runtime binding
  warnings and rendering are recorded as not checked.

  The fixture is test code only, about one small class. It is needed because
  azzurro's demo-player answers polls promptly with changing etags rather than
  holding them, so it cannot exercise timeout or offline timing
  deterministically. The configurable fake-player library is only usable from
  Rust test code.

**B. Removed (Misja, 2026-11-06).** The optional check against azzurro's Rust
`demo-player` would add a foreign toolchain and container for little gain. The
independent check is a manual test against a real player once a device
installation is approved; until then it is recorded as not performed. LSDP end
to end is covered by unit tests (A) and that device check.

Harbour validator: run `sdk-harbour-rpmvalidator` from the target on the built
RPM. No full rebuild of SDK components is needed.

## Risks, approval boundaries and remaining decisions

- No device installation, remote repository, OBS/Chum or Harbour submission
  is in this increment.
- Risk: 5.1→5.2 compatibility is unproven until a runtime check on 5.2.
- Risk: protocol drift. Mitigated by pinning API v1.7 and ignoring unknown
  elements.
- Risk: QtTest timing under qemu emulation. Mitigated by the step 1 spike and
  injectable timeouts.
- Decided: private GitHub repository misja/swell, issue #1.
- Risk: Silica may not load on the `minimal` platform (AC4 spike decides).
- Known limitation: during the attached-page swipe the docked panel hides as
  the swipe starts; any remaining overlap is recorded after a device check.
