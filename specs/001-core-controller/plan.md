## Design and repository ownership

Single repository `swell` (owner: Misja), app id `harbour-swell`,
organization/application names for Sailjail decided at scaffold time.

C++/QML split. Each part records why it is in C++, as the spec requires:

| Part | Where | Reason |
|---|---|---|
| LSDP discovery (`LsdpDiscovery`) | C++ | QML has no UDP socket. QUdpSocket on port 11430. Sends seven queries at 0, 1, 2, 3, 5, 7 and 10 s with up to 250 ms jitter (API v1.7 Appendix, timing) and keeps listening for announces. Handles Announce and Delete messages and skips unknown types. |
| LSDP packet parser (`lsdp::parse`) | C++, pure function | Tested with QtTest on synthetic byte arrays. Cases: truncated packet, unknown type, own echoed `Q`, several messages, an announcement split across messages (API Appendix note 2), a Delete message, the class filter, and an address change for the same node id. The control port comes from TXT `port`, falling back to 11000. Name and model are taken from TXT when present; `/SyncStatus` is authoritative. |
| Player client (`PlayerClient`, one per player) | C++ | Reason: the long-poll, one-second-rule and backoff state machine must be covered by QtTest (AC3). Timeouts use `QTimer` + `abort()`: Qt 5.6 has no transfer timeout in either QNetworkRequest or QML XHR, as checked in `libQt5Qml.so.5.6.3`. All players share the app's single QNetworkAccessManager, which is also the QML engine's NAM. The one-second rule is keyed by request path (API §2: "must"). Bursts of commands to the same path, such as volume from a slider, collapse to the latest value. Offline state and backoff. Commands: play, pause, skip, back, volume and mute. |
| Polling policy | C++ (`PlayerClient`) | `/Status` long poll with `timeout=100` (API §2.1 recommends 100 s and never less than 10 s; tests inject shorter values). `/SyncStatus` is fetched once when a player is added (name, model, id, group master) and again whenever `<syncStat>` in `/Status` changes. This player's volume and mute come from `/SyncStatus`, because a grouped secondary's `/Status` copies the primary's (API §2). |
| XML parsing (`parseStatus`, `parseSyncStatus`, `parseVolume`) | C++, QXmlStreamReader, pure functions | Unknown elements are ignored and malformed input returns an error value. QtTest coverage without a network. |
| Player model (`PlayerModel`) | C++ QAbstractListModel | Merges discovered and manual players by node id / `host:port`. |
| UI: player list, Now Playing, add-player dialog, About/privacy | QML/Silica | Standard Silica pages. |
| Cover page and cover actions | QML/Silica | `CoverActionList`. |
| Persistence (manual hosts, last selection) | QML `Nemo.Configuration` (`ConfigurationValue`) | Existing allowed platform facility; no own storage code. |
| Cover art | C++ helper `artworkUrl()` + QML `Image` | The helper resolves relative image paths against the player and adds `followRedirects=1` (API v1.7 image attributes). `Image` loads through the shared NAM, which also follows redirects as a fallback. |
| Translations | `qsTr()` + `translations/*.ts`, `CONFIG += sailfishapp_i18n` | As in the SDK template. |

No threads besides Qt's own network handling; everything runs on the event loop.

Layout: `src/` (C++), `qml/`, `translations/`, `rpm/harbour-swell.spec`,
`harbour-swell.desktop` (`[X-Sailjail] Permissions=Internet`;
OrganizationName must not be com.jolla or org.sailfishos), `icons/` with the
template's `SAILFISHAPP_ICONS = 86x86 108x108 128x128 172x172`, `tests/`
(QtTest, `CONFIG += testcase`, never installed), `tools/test-player/`
(container scripts, see below). The RPM `%files` stay as in the template:
only `/usr/bin/harbour-swell`, `/usr/share/harbour-swell`, the desktop file
and the icons (the validator's `rpmvalidation.conf`). Configuration keys
live under `/<org>/harbour-swell/`; dconf is already allowed by
`Base.permission`.

## Validation

Two test layers.

**A. In-process QtTest** (acceptance criteria 2 and 3; this layer gates
completion). Built with `CONFIG += testcase` and run with `make check` in the
SDK build engine for the aarch64 target (sb2/qemu; see the spike above):
- Parser and LSDP unit tests on synthetic fixtures written for this project.
- `PlayerClient` against a `QTcpServer` fixture in the same test process on
  loopback. It covers:
  - long-poll hold until the etag changes or the timeout expires;
  - an unchanged-etag timeout;
  - the one-second rule;
  - server stop/start, which must give offline then recovered;
  - a host that is not a BluOS player;
  - the request log for transport, volume and mute, including a collapsed
    volume burst;
  - `/SyncStatus` refetch on a `<syncStat>` change;
  - `/Artwork` redirect: an image fetched through the shared NAM follows a
    redirect to a second fixture port, and `artworkUrl()` adds
    `followRedirects=1`.

  The fixture is test code only, about one small class. It is needed because
  azzurro's demo-player answers polls promptly with changing etags rather than
  holding them, so it cannot exercise timeout or offline timing
  deterministically. The configurable fake-player library is only usable from
  Rust test code.

**B. Optional independent integration check against azzurro `demo-player`**
(non-gating; done only after Layer A passes). It checks Swell's client against
another project's reading of the protocol, not only against our own fixtures.
- Container `swell-test` (LXC, Ubuntu 26.04, unprivileged). The maintainer
  approved this on 2026-11-06 ("lxc container voor fakeplayer en ander werk").
  - Build phase: temporary NIC on `br0` for apt, the Rust toolchain and the
    crates download.
  - Toolchain: the Ubuntu 26.04 archive's `rustc`/`cargo` if it is ≥ 1.98;
    otherwise rustup with the exact pinned `1.98.0` inside the container only.
  - Build: `cargo build --locked -p fake-player --example demo-player` at
    commit 9375da6. Record the toolchain version and Cargo.lock hash.
  - Run phase (Misja, 2026-11-06): the container stays on the existing `br0`
    with its own LAN address. The Docker build engine already reaches the LAN
    through the existing masquerade rule of `sailfish-sdk`, so no new bridge,
    no extra NIC and no host change are needed. demo-player binds its three
    rooms to addresses inside the container: loopback aliases are not
    reachable from outside, so rooms are given distinct ports or extra
    addresses on the container's interface (decided at execution). It runs
    **without `--announce`**, so no LSDP announcements reach the LAN or the
    official BluOS controller. The rooms are added by address. Accepted
    exposure: the fake rooms answer HTTP to the LAN while the test runs; they
    serve invented data only and never contact real players. The container is
    stopped after the run.
- Check: the same QtTest binary has an integration test that runs only when
  `SWELL_TEST_HOST` is set; there is no separate CLI program. It adds the
  three rooms by address, verifies `/Status` and `/SyncStatus` parsing and a
  long-poll cycle, and checks that play, pause, skip, volume and mute change
  the state the player reports.
- LSDP end to end is not testable here, because broadcasts do not cross the
  Docker NAT. It is covered by unit tests (A) and the device check. This is
  recorded as a limitation, not marked as passed.

Harbour validator: run `sdk-harbour-rpmvalidator` from the target on the built
RPM. No full rebuild of SDK components is needed.

## Risks, approval boundaries and remaining decisions

- Layer B uses only the approved `swell-test` LXC container on `br0`. Docker
  stays inside containers, never on the host. A focused separate review of
  this isolation change is due before Layer B runs.
- No device installation, remote repository, OBS/Chum or Harbour submission
  is in this increment.
- Risk: 5.1→5.2 compatibility is unproven until a runtime check on 5.2.
- Risk: protocol drift. Mitigated by pinning API v1.7 and ignoring unknown
  elements.
- Risk: QtTest timing under qemu emulation. Mitigated by the step 1 spike and
  injectable timeouts.
- Open: remote location and issue tracker.
